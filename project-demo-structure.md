# HelpDesk Lite — Project Demo Structure

## 1. Problem

Internal support requests are currently handled through multiple channels. This can create unclear ownership, inconsistent follow-up, repeated clarification, and limited visibility into open, delayed, and completed requests.

HelpDesk Lite addresses this problem by providing a centralized workspace for managing support requests as trackable tickets.

## 2. Scope

### In Scope

- Creating support tickets
- Viewing and managing tickets
- Assigning ticket ownership
- Setting ticket priority
- Tracking ticket status
- Following ticket progress
- Providing visibility into ticket activity

### Out of Scope

- Advanced automation
- External customer support
- Complex reporting and analytics
- Third-party system integrations
- Features outside the initial internal support workflow

## 3. Key Decisions

The project uses a simple and consistent ticket workflow:

**Create → Assign → Prioritize → Work → Resolve → Close**

Key decisions include:

- Centralizing support requests into one workspace
- Making ticket ownership explicit
- Using priority and status to support follow-up
- Keeping the initial scope focused on core ticket management
- Prioritizing usability and clarity over unnecessary features

## 4. Evidence

The project will be demonstrated using:

- GitHub repository and commit history
- Project documentation and README
- Screenshots of the implemented workflow
- Ticket management interface
- Evidence of ticket status, priority, and ownership
- Review and iteration documentation

The evidence is intended to show both what was built and how the project decisions are supported.

## 5. Next Steps

After the demo, the proposed next steps are:

1. Validate the workflow with stakeholders.
2. Confirm ticket status and priority rules.
3. Collect feedback from intended users.
4. Address high-priority usability issues.
5. Prepare the project for the next implementation or testing stage.

## Demo Flow

The presentation will follow this order:

**Problem → Scope → Key Decisions → Evidence → Next Steps**

The demo will explain the reasoning behind the project before showing the implementation evidence.
